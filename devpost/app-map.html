Saathi App Map

A take-home guide to where things live in Saathi. Snapshot of the code at commit 021591a; it can drift as the code changes.

The app in one paragraph

The web page (client/, React + Tailwind) shows the customer's phone on the left and the bank side on the right. The server (server/, Express) keeps a fictional bank in memory. When a bill photo arrives, the server asks Gemini to read it and give a reason, then the server's own rules decide the amount, check balance and duplicates, and wait for the customer's Approve. Anything above PKR 25,000 waits for a bank officer. Every step goes into the activity log, masked.

One action, followed through the code: "send a bill photo"

Reference route (3 stops)

A reference route prepared from the finished code; not yet toured together.

1
client/src/components/ChatInput.jsx, function attach and send. The photo (or a sample bill from client/public/samples/) goes through prepareImage in client/src/lib/image.js, which shrinks it and strips camera metadata, then is posted to /api/chat.
2
server/src/agent.js, function askSaathi (search SCHEMA and instructions). Builds the prompt, swaps typed numbers for [NUM1] placeholders (tokenize in server/src/mask.js), and asks Gemini for JSON in a fixed shape. Without a key it uses server/src/samples.js (demo mode).
3
server/src/rules.js, functions preparePayment, onCustomerApprove, review, execute. The only code that decides about money: late amount if overdue, balance, duplicates, the approvalLimit() (PKR 25,000), and the mock payment with a receipt. Each step calls addLog with a reason.

To change this, start here

  • The approval limit: APPROVAL_LIMIT in .env, or approvalLimit in server/src/rules.js.
  • What Saathi is told to do: the instructions text in server/src/agent.js.
  • What the customer is told after a decision: server/src/messages.js (English, Roman Urdu, Urdu).
  • The customer and starting balance: fresh() in server/src/store.js.
  • Colours and card layout: client/src/components/PaymentCard.jsx (STATUS).
  • The bank side: client/src/components/OfficerDesk.jsx and ActivityLog.jsx.

A practice to reuse

Let the AI explain, let code decide, and test the code without the AI. The PRD's product decision ("The AI reads and explains; fixed code decides limits, balance, duplicates and execution") became server/src/rules.js, which server/test/rules.test.js and server/test/api.test.js check with no AI call at all (17 tests, npm test). The first real Gemini run then found a gap the tests had missed: dates were being masked as if they were account numbers. That became a new test in server/test/mask.test.js. On another project, the same split works for anything an AI prepares and a person must approve: keep the decision in plain, tested code, and log the AI's reason next to it.

Run it again

npm install, copy .env.example to .env and add GEMINI_API_KEY, then npm run dev and open http://localhost:5173. npm test runs the checks. Without a key it runs in labelled demo mode.
